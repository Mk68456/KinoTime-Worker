KinoTime Worker — отдельный слот Bothost

Этот архив является отдельным Git-проектом. НЕ загружайте его поверх основного KinoTime.
Ни токенов, ни Telegram-сессии, ни базы каталога в архиве нет.

1. Создайте отдельный репозиторий и загрузите весь архив в его корень.
2. Создайте отдельного служебного бота в BotFather. Его токен требуется форме Bothost.
   Не используйте токен основного KinoTime. Код обработчика BOT_TOKEN не читает
   и сообщения служебного бота не обрабатывает.
3. В Bothost: название KinoTime Worker; Telegram; Python 3.11; Нидерланды.
   Git URL — новый репозиторий, ветка main. Главный файл main.py.
   Домен выключен; собственный Dockerfile выключен.
   Переменные ДО создания слота: DATA_DIR=/app/data, PYTHONUNBUFFERED=1.
4. Нужна отдельная пользовательская Telegram-сессия. На своём компьютере
   в окружении Python 3.11 с зависимостями из requirements.txt выполните:
   python -m tools.authorize_instant --panel https://АДРЕС-ОСНОВНОЙ-ПАНЕЛИ
   Вход, код Telegram и пароль вводит сам владелец. Telegram API ID/hash —
   ваши данные приложения с my.telegram.org. Для кода подключения отправьте
   /desktop основному KinoTime и введите выданный код по запросу программы.
   Файлы появятся в runtime/yougen-server. Не добавляйте их в Git.
5. Через файловый менеджер Bothost загрузите bridge.json и provider.session
   в /app/data/yougen/ нового слота. Если загрузка до первого запуска недоступна,
   сначала создайте слот: без файлов он завершится с понятной ошибкой.
   После загрузки перезапустите слот. Путь сессии автоматически переносится
   в DATA_DIR/yougen/provider.session, данные конфигурации не выводятся в логи.
6. Перед включением нового обработчика остановите старый на компьютере,
   дождавшись окончания активной передачи. Не запускайте оба обработчика вместе.
7. Проверка: в логе нового слота есть строка запуска Worker; /instant_status
   в основном KinoTime показывает обработчик; пробный запрос проходит при
   выключенном обработчике компьютера. Только после проверки перенос завершён.

Основной бот остаётся в своём слоте. INSTANT_AGENT_ENABLED в основном слоте
должен оставаться 0 при отдельном Worker. Режим выдачи и автоматическая публикация
настраиваются отдельно в основном боте; этот комплект их не меняет.

Ограничения: слот Bothost должен сохранять /app/data и разрешать исходящие
соединения с Telegram и HTTPS-панелью. Это пока не проверено запуском на хостинге.
Полная работоспособность сервера подтверждается только пунктом 7.
При ошибке входа обработчик сам не запрашивает код и не начинает новую авторизацию.
